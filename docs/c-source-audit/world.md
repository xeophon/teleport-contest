# World generation and persistent state audit

Source: `nethack-c/upstream/src` at `16ff59115315917b93185d026aeefea06db9b0f4` and its `dat/*.lua` inputs. This is a review of the function bodies and JS call paths listed below, covering all 29 assigned files. It is not an assertion that every branch of every function has been ported. Native file formats and Lua bindings are distinguished from missing gameplay behavior. Existing tests listed here are evidence for particular behavior, not whole-file parity.

## Implemented quest filler group

`js/mklev.js` now dispatches the upper and lower filler programs for Caveman, Healer, Knight, Monk, Ranger, Rogue, Samurai, Tourist, and Valkyrie. The 18 upstream `*-fila.lua`/`*-filb.lua` files are compiled by `tools/generate-quest-fillers.mjs` into `js/quest_filler_data.js`. The generator rejects syntax outside the supported declarative subset and has an exact regeneration check. Runtime generation uses the existing cave generator, room allocator, corridors, object/monster creation, trap creation, wallification, flips, and finalization.

The programs preserve declaration order, including alignment shuffle, randomized initial lighting, cave generation, stairs, objects, traps, and inhabitants. Placement follows `sp_lev.c:get_location` (1202), `is_ok_location` (1280), `pm_to_humidity` (1884), `create_monster` (1925), `lspo_room` (4028), and `l_create_stairway` (4147). Water-preferring monsters first search wet squares; the fixed Samurai map uses the odd centered coordinates from `lspo_map` (6075). Room contents are skipped when C's room creation cannot find a placement. `mkroom.c:inside_room` (678), including the boundary squares of ordinary rooms, is reused through the existing JS helper.

`test/quest-fillers.test.mjs` adds 26 tests: exact source regeneration, all 18 dispatches with source-required inhabitants/objects/stairs across three live seeds, fixed ASCII geometry, eel placement in pools, initialization RNG order for three layout families, and repeatability/variation. The first run had 24 failing tests and two passing tests. The completed suite and existing `special-levels`/`levelgen-rolls` suites pass 42/42. These checks do not establish complete C RNG equality for all downstream inventory and population branches.

There were 19 implemented quest program dispatches among 65 role/program combinations before this group; there are now 37. The remaining 28 are special start/locate/goal maps, not additional ordinary filler levels. This is a map-dispatch count, not a percentage of the C game implemented.

The class-monster gender assignment was independently checked: `lspo_monster` initializes `female = 0` at 3230; a class-string argument leaves it unchanged, and an unspecified class-table gender falls back to zero at 3355. `create_monster` writes that value over the generated monster's gender at 2125. Named monsters instead receive the species-aware gender from `find_montype` (3143). The new executor preserves this source behavior.

## Shared lighting and anatomy follow-up

`vision.js` now resolves active floor, hero-carried, and monster-carried object lights on every recalculation. It uses C candle-stack/candelabrum radii, lamp/oil radii, active Sunsword and worn gold-dragon armor blessing radii, the existing circle table, and the shared `clear_path` quadrants. Hero-centered sources use `COULD_SEE`; buried/contained objects do not illuminate the map. Monster, polymorphed hero, and steed sources use their current location. C deliberately gives all luminous monster species radius one; this port keeps that value. Normal blind vision bypasses source lighting as in C, while refresh and Rogue vision still run it.

`test/vision-light-sources.test.mjs` has 31 passing tests, including circle geometry, four-quadrant obstruction, moving owners, extinguishing, candle thresholds, artifact/armor states, hidden sources, polymorph, steed position, and zero RNG consumption. A separate source-derived check preserves the distinction between buried monster light (suppressed by `get_mon_location`) and its carried object light (`get_obj_location` checks only the carrier's map position). The initial 28-test run had 27 failures; two provisional refresh/Rogue expectations were corrected after inspecting the exact source call placement. No historical test or recording was changed. Fuel expiration, automatic artifact activation/deactivation, camera flashes, and generic light-source save/relink behavior remain separate lifecycle gaps.

For the pit-climbing caller, `js/mondata.js` now implements `bodyPart`, `locomotion`, and `heroLocomotion` from `polyself.c:mbodypart` (1972), `mondata.c:locomotion` (1380), and `hack.c:u_locomotion` (1817). Its 53 tests compare all 19 selectors against each of the 12 C anatomy tables and exercise species exceptions and movement-word precedence. The source-wide `trapmove` caller check confirmed that ordinary walking passes a null destination trap (`hack.c` 2831), so it attempts to climb before entering an adjacent pit. This is separate from direct pit-entry effect handling.

The latest combined focused run passed 166/166: quest fillers, lighting, anatomy, command bindings (including one prototype-name regression found during cross-review), gas regions, special levels, and level-generation rolls. This does not replace the root task's full unit/public validation.
