## What the evidence means

The port has no one-to-one C/JS file layout. Much of the gameplay is in `cmd.js`, `allmain.js`, and `mklev.js`; a missing `foo.js` does not show that `foo.c` is unimplemented. Conversely, a helper, command name, field, or damage-result flag does not establish that all required effects happen through the runtime caller. Canonical monster data in `permonst.js` and legacy runtime species records use different fields, which also matters when checking predicates.

Each report separates these outcomes:

- **Implemented and tested slice:** named C behavior, a live JS owner/caller, and assertions of its state, output, or RNG consequences. Red-to-green results are recorded where the behavior was first reproduced as failing.
- **Confirmed remaining omission:** an inspected source operation or branch lacks its effect in the corresponding JS path. These form the backlog below.
- **Unverified scope:** source or JS ownership was located, but equivalence was not established. This is not a claim of absence.
- **Platform replacement:** browser storage, static imports, JS allocation, and browser input replace native file formats, archives, heap management, and window backends. They need appropriate integration checks, not arbitrary same-name modules.

The [port-state report](../PORT_STATE.md) owns the final full-suite, public-recording, supplemental-recording, and playability results. Those are separate denominators. A perfect score on the available public recordings is not a percentage of NetHack implemented. Targeted test totals in the partition reports overlap and must not be added together as independent coverage. No source branch is marked complete solely because a recording passed.

## Continuing the audit

For each next slice, record the source function and line, current JS owner, a failing state-based case, the final runtime caller, and remaining branches. Prefer a shared source operation over another name-specific list or duplicated command path. Keep baseline and final recording results separate from these behavior tests, and preserve source attribution and generated-data checks.

The inventory hashes make it possible to notice reference changes; the ownership reports need refreshing when C or JS call paths change. They are a bounded, reviewable map of current evidence, not a completion certificate.
