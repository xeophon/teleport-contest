# 07. Traps, Liquids, Terrain, and Object Damage Audit

Scope: upstream C under `nethack-c/upstream` and current JS under `js/`. This audit covers trap creation and triggering, post-move terrain effects, water/lava/ice/liquid behavior, fire/cold/ray floor effects, burial and earthquake effects, and object material damage. It only uses repository-visible C and JS behavior; it does not infer anything from private suites or recommend hardcoded answers.

## Upstream C Shape

C creates traps through `maketrap()`, which rejects impossible terrain, initializes trap state, and performs trap-specific setup such as statue contents, rolling boulder launch data, and portal/teleport destinations (`nethack-c/upstream/src/trap.c:456`). Triggering is centralized through individual `trapeffect_*()` routines and a single `trapeffect_selector()` dispatch (`nethack-c/upstream/src/trap.c:1190`, `nethack-c/upstream/src/trap.c:1251`, `nethack-c/upstream/src/trap.c:1324`, `nethack-c/upstream/src/trap.c:1479`, `nethack-c/upstream/src/trap.c:1595`, `nethack-c/upstream/src/trap.c:1730`, `nethack-c/upstream/src/trap.c:1825`, `nethack-c/upstream/src/trap.c:2013`, `nethack-c/upstream/src/trap.c:2070`, `nethack-c/upstream/src/trap.c:2088`, `nethack-c/upstream/src/trap.c:2106`, `nethack-c/upstream/src/trap.c:2453`, `nethack-c/upstream/src/trap.c:2528`, `nethack-c/upstream/src/trap.c:2661`, `nethack-c/upstream/src/trap.c:2937`). The hero uses `dotrap()` and monsters use `mintrap()`, so air/flying exceptions, seen-trap escape chances, Sokoban exceptions, monster trap knowledge, anger/blame, and trap deletion all flow through one model (`nethack-c/upstream/src/trap.c:2996`, `nethack-c/upstream/src/trap.c:3733`).

C terrain effects are also centralized. `spoteffects()` is the post-move spot pipeline: it handles pools/lava, sinks, autopickup ordering, trap triggering, pit exceptions, recursion protection, and ice warnings after movement or teleport placement (`nethack-c/upstream/src/hack.c:3312`). `float_down()` reuses the same terrain/trap stack when levitation ends (`nethack-c/upstream/src/trap.c:4024`). Object landing behavior is handled by `flooreffects()`, called by drop/throw/kick paths, and covers boulders filling liquids or pits, liquid/fire/hot-ground damage, pit/hole falling, glob merging, altar effects, and billing-sensitive floor interactions (`nethack-c/upstream/src/do.c:29`, `nethack-c/upstream/src/do.c:162`, `nethack-c/upstream/src/do.c:786`, `nethack-c/upstream/src/do.c:800`, `nethack-c/upstream/src/do.c:807`).

C liquid behavior has dedicated hero, monster, and object paths. Hero water/lava resolution is in `drown()`, `lava_effects()`, and `sink_into_lava()`, including water inventory damage, life-saving/death cases, swimming and breathless forms, teleport escape, water walking, fire resistance, lava entrapment, and vision/state transitions (`nethack-c/upstream/src/trap.c:5059`, `nethack-c/upstream/src/trap.c:6794`, `nethack-c/upstream/src/trap.c:6991`). Monster liquid handling is in `minliquid()`, including eels on dry land, gremlin splitting, iron golem rusting, teleport-away checks, drowning/burning, and monster inventory water/fire damage (`nethack-c/upstream/src/mon.c:947`). Floor and container item damage is split into `water_damage()`, `water_damage_chain()`, `fire_damage()`, `fire_damage_chain()`, and `lava_damage()` (`nethack-c/upstream/src/trap.c:4455`, `nethack-c/upstream/src/trap.c:4550`, `nethack-c/upstream/src/trap.c:4576`, `nethack-c/upstream/src/trap.c:4712`, `nethack-c/upstream/src/trap.c:4855`).

C rays and terrain are concentrated in `zap_over_floor()`. Fire burns webs, melts ice, evaporates pools/moats into pits or gas, dries fountains, and calls floor object burning; cold freezes pools/moats/lava/lava walls, buries objects under new ice, starts melt timers, and handles doors and ray range changes (`nethack-c/upstream/src/zap.c:4598`, `nethack-c/upstream/src/zap.c:5040`, `nethack-c/upstream/src/zap.c:5088`, `nethack-c/upstream/src/zap.c:5141`). Inventory destruction from elemental damage uses `maybe_destroy_item()` and `destroy_items()`, while generic erosion is routed through `erode_obj()` and object material predicates (`nethack-c/upstream/src/zap.c:5798`, `nethack-c/upstream/src/zap.c:5965`, `nethack-c/upstream/src/trap.c:171`).

C burial and earthquakes share floor-object state. `bury_an_obj()`, `bury_objs()`, `unearth_objs()`, and `rot_organic()` move objects between floor and buried lists, preserve punishment ball/chain behavior, stop lights/leashes, account for shop debt, and start organic rot timers (`nethack-c/upstream/src/dig.c:1984`, `nethack-c/upstream/src/dig.c:2050`, `nethack-c/upstream/src/dig.c:2086`, `nethack-c/upstream/src/dig.c:2125`). Earthquakes are generated by `do_earthquake()` and `do_pit()`, which collapse terrain, create pits/chasms, settle boulders, wake or expose monsters, and apply hero/monster pit outcomes (`nethack-c/upstream/src/music.c:221`, `nethack-c/upstream/src/music.c:344`).

## Current JS Shape

JS trap creation has a C-shaped entry point in `maketrap()` with terrain checks, pit/hole normalization, notes, statue traps, rolling boulder launch data, teleport/portal destinations, and levelgen use sites (`js/mklev.js:7104`, `js/mklev.js:7127`, `js/mklev.js:7197`, `js/mklev.js:7227`). Wish-side selected wizard traps, including the beartrap/land-mine object-vs-armed-trap ambiguity, now reuse that creation path; wizard terrain/furniture wishes also create C-shaped map results for water/lava/ice, altars, graves, trees, bars, clouds, doors, walls, corridors, floors, and drawbridge under-terrain state. Runtime trap effects and terrain side effects such as liquid object damage remain separate parity areas. Runtime trap effects are split by context: movement handles transport, teleport, rust, fire, rolling boulder, and statue traps directly inside `moveHero()`; sitting has a fuller `sitTriggerTrap()` trap dispatcher; monsters use `monsterTriggerTrap()`, `monsterTeleportTrapEffect()`, `monsterTrapHarmless()`, and `monsterFireTrapEffect()` (`js/cmd.js:20122`, `js/cmd.js:20449`, `js/cmd.js:20482`, `js/cmd.js:20617`, `js/cmd.js:21844`, `js/allmain.js:7738`, `js/allmain.js:7800`, `js/allmain.js:7835`, `js/allmain.js:7945`).

JS has a substantial floor-object effects layer. `earthFloorEffects()` handles boulders in liquids, boulders plugging pits/holes, object water/lava/hot-ground effects, glob merging, and altar flashes; it is used by scroll of earth, monster drops, monster-thrown objects, magic-bag scatter landings, and several landing helpers (`js/cmd.js:12869`, `js/cmd.js:12963`, `js/cmd.js:12972`, `js/cmd.js:13776`, `js/cmd.js:14175`). Water/fire/lava object damage is factored into floor and inventory helpers, with container spill queues, separate acid-context handling, and an opt-in used-up shop-bill preservation path for destructive scatter landings (`js/cmd.js:7429`, `js/cmd.js:7516`, `js/cmd.js:7552`, `js/cmd.js:7762`, `js/cmd.js:7864`, `js/cmd.js:7941`, `js/cmd.js:7999`, `js/cmd.js:8042`).

JS ice and burial behavior is concentrated in `js/ice.js`. It has melt timers, ice-to-liquid restoration, object ice effects, buried-object lists, buried ball transitions, buried organic rot scanning, cold ray freezing, lava wall solidification, and unearthing after melt (`js/ice.js:114`, `js/ice.js:136`, `js/ice.js:323`, `js/ice.js:328`, `js/ice.js:365`, `js/ice.js:430`, `js/ice.js:573`, `js/ice.js:578`, `js/ice.js:725`, `js/ice.js:757`, `js/ice.js:928`, `js/ice.js:1021`). Monster liquid handling is split between normal monster turns and terrain-change callbacks: `monsterMinliquid()` covers eel dry-land behavior and lava, while `applyMonsterLiquidEffectsAt()` handles post-melt/post-flow water/lava consequences (`js/allmain.js:7361`, `js/monster_liquid.js:173`, `js/monster_liquid.js:269`, `js/monster_liquid.js:290`, `js/monster_liquid.js:321`).

JS fire ray terrain lives mostly in `fire_breath.js`, with separate handlers for burning web traps, melting ice, evaporating or steaming water, drying fountains, and applying fire breath damage to monsters/heroes (`js/fire_breath.js:219`, `js/fire_breath.js:327`, `js/fire_breath.js:340`, `js/fire_breath.js:384`, `js/fire_breath.js:410`, `js/fire_breath.js:449`, `js/fire_breath.js:497`). Cold ray terrain is in `applyColdRayTerrain()`, not in the fire ray file (`js/ice.js:928`). Earthquake behavior is implemented in `doEarthquake()`, with pit creation and per-square pit effects, and the drum path calls it through command handling (`js/cmd.js:3250`, `js/cmd.js:3273`, `js/cmd.js:3465`, `js/cmd.js:3523`, `js/cmd.js:32019`).

JS object material damage currently uses a mix of object fields, kind/name inference, profile helpers, and local regex/class checks. Examples include `wishedDamageProfile()`, `erosionVerb()`, `erodeDestroyArmor()`, rust trap item damage, floor erosion, direct lava material sets, and fire/cold inventory selectors (`js/cmd.js:14348`, `js/cmd.js:14366`, `js/cmd.js:15056`, `js/cmd.js:7429`, `js/cmd.js:7762`, `js/cmd.js:7864`, `js/cmd.js:7941`, `js/cmd.js:8042`).

## Concrete Gaps

1. There is no single JS equivalent of C `spoteffects()`. C has one post-placement pipeline for liquid, sink, pickup, trap, and ice handling (`nethack-c/upstream/src/hack.c:3312`). JS spreads this across `moveHero()`, movement trap branches, liquid avoidance/death messages, floor-effect helpers, ice callbacks, and monster-turn code (`js/cmd.js:21844`, `js/cmd.js:13776`, `js/ice.js:1021`, `js/allmain.js:7361`). This makes ordering differences likely, especially around autopickup versus traps, pit exceptions, terrain transformed under the hero, and levitation ending.

2. Hero trap behavior is context-dependent instead of selector-driven. C uses `trapeffect_selector()` from both `dotrap()` and `mintrap()` (`nethack-c/upstream/src/trap.c:2937`, `nethack-c/upstream/src/trap.c:2996`, `nethack-c/upstream/src/trap.c:3733`). JS has a fuller sitting dispatcher, but ordinary movement handles only selected traps inline; for example movement over a rust trap only rolls `rn2(5)` and prints a gush message, while `sitRustTrapMessage()` performs actual water damage routing (`js/cmd.js:20449`, `js/cmd.js:20617`, `js/cmd.js:21844`). Trap results can diverge by whether the hero moved, sat, or a monster stepped.

3. Monster trap effects are partial relative to C `mintrap()`. C applies the same trap family with monster-specific outcomes, trap memory, anger/blame from hero-made traps, harmless checks, and already-trapped escape behavior (`nethack-c/upstream/src/trap.c:3733`). JS currently has trap learning, teleport, harmless checks, and fire trap effects, but many trap types either short-circuit as harmless or lack full monster-specific consequences in the shared path (`js/allmain.js:7738`, `js/allmain.js:7800`, `js/allmain.js:7835`, `js/allmain.js:7945`).

4. Hero liquid handling is not modeled as C `drown()`/`lava_effects()`. C tracks `uinwater`/underwater, drowning, water damage, swimming, breathless forms, gremlin and iron golem special cases, teleport escape, water walking, life-saving, fire resistance, and lava entrapment (`nethack-c/upstream/src/trap.c:5059`, `nethack-c/upstream/src/trap.c:6794`, `nethack-c/upstream/src/trap.c:6991`). JS movement mostly avoids liquid unless the `m` prefix is used, then applies immediate crawl-out or lava death messages inside `moveHero()` (`js/cmd.js:21844`). Ice melt and cold-ray callbacks update some `uinwater`/lava-adjacent state, but there is no reusable hero liquid resolver.

5. Monster liquid handling is split and incomplete. C `minliquid()` is a turn-level check for monsters standing in or leaving liquids, and it handles both water and lava plus special species and inventory damage (`nethack-c/upstream/src/mon.c:947`). JS has one normal-turn path for eels and lava, plus a richer callback used when terrain changes into liquid (`js/allmain.js:7361`, `js/monster_liquid.js:290`). A monster entering or remaining in ordinary pools does not obviously pass through one C-like `minliquid()` gate in all contexts.

6. Floor object effects are implemented but not uniformly owned. C `flooreffects()` is the common object landing contract for drops, throws, kicks, boulders, liquids, traps, globs, altars, and shop side effects (`nethack-c/upstream/src/do.c:162`). JS `earthFloorEffects()` is strong coverage for many of those mechanics, but it is an opt-in helper used by specific callers (`js/cmd.js:13776`, `js/cmd.js:13835`, `js/cmd.js:13999`, `js/cmd.js:16771`, `js/cmd.js:33097`). Any object path that lands, spills, migrates, is created by terrain change, or drops from monster death must be audited individually to ensure it reaches the same floor-effect stack.

7. Fire/cold/ray terrain behavior is path-specific. C `zap_over_floor()` owns fire, cold, evaporation, freezing, door interactions, web burning, ice timers, object burning, shop damage, and ray range changes from one ray floor hook (`nethack-c/upstream/src/zap.c:5141`). JS splits fire breath/ray handling and cold ray handling between `fire_breath.js`, `cmd.js`, and `ice.js` (`js/fire_breath.js:219`, `js/fire_breath.js:327`, `js/fire_breath.js:340`, `js/fire_breath.js:384`, `js/cmd.js:7552`, `js/ice.js:928`). Current coverage is meaningful for visible fire/cold paths, but it is not one ray-floor contract shared by every zap/breath/explosion source.

8. Ice timers and burial use JS field/scanner state rather than C timer/list semantics. C starts terrain/object timers and moves buried objects through level object lists with relinking-sensitive state (`nethack-c/upstream/src/zap.c:5088`, `nethack-c/upstream/src/dig.c:1984`, `nethack-c/upstream/src/dig.c:2050`, `nethack-c/upstream/src/dig.c:2086`, `nethack-c/upstream/src/dig.c:2125`). JS has `meltIceTimers`, buried flags/lists, and organic rot turn fields (`js/ice.js:114`, `js/ice.js:725`, `js/ice.js:757`, `js/ice.js:1021`). That can work, but it needs explicit save/restore, off-level catchup, object identity, and unearth ordering parity with C.

9. Earthquake behavior is present but should be tied to the same terrain/floor contracts. C `do_earthquake()` and `do_pit()` reuse pit creation, liquid filling, boulder/object effects, monster exposure, and terrain collapse (`nethack-c/upstream/src/music.c:221`, `nethack-c/upstream/src/music.c:344`). JS has `doEarthquake()`, `makeEarthquakePitTrap()`, and `doEarthquakePit()` (`js/cmd.js:3273`, `js/cmd.js:3465`, `js/cmd.js:3523`). The gap is less "missing earthquake" and more that earthquake-created pits and collapses need to call the same future trap/liquid/floor-effect primitives as movement, drops, and rays.

10. Object material damage is not table-driven enough. C erosion and destruction consult object metadata and material predicates through `erode_obj()`, `destroy_items()`, `water_damage()`, `fire_damage()`, and `lava_damage()` (`nethack-c/upstream/src/trap.c:171`, `nethack-c/upstream/src/trap.c:4455`, `nethack-c/upstream/src/trap.c:4576`, `nethack-c/upstream/src/trap.c:4712`, `nethack-c/upstream/src/zap.c:5965`). JS frequently infers material and destroyability from names, classes, regexes, `wishedDamageProfile()`, and local sets (`js/cmd.js:7762`, `js/cmd.js:7864`, `js/cmd.js:7941`, `js/cmd.js:15056`). This is fragile for generated objects, special artifacts, future object data imports, and container contents.

11. Inventory and floor damage paths duplicate rules. C has shared item-damage mechanisms with context-specific feedback and chain traversal (`nethack-c/upstream/src/trap.c:4455`, `nethack-c/upstream/src/trap.c:4550`, `nethack-c/upstream/src/trap.c:4712`, `nethack-c/upstream/src/trap.c:4855`, `nethack-c/upstream/src/zap.c:5798`). JS has separate hero inventory, monster inventory, floor, rust trap, liquid flow, lava, and fire ray helpers (`js/cmd.js:7429`, `js/cmd.js:7762`, `js/cmd.js:7864`, `js/cmd.js:7999`, `js/cmd.js:8042`, `js/monster_liquid.js:173`). The duplication makes it easy for blessed/oerodeproof/greased/oilskin/book/artifact/potion behavior to diverge by damage source.

12. Shop, blame, and visibility side effects are local rather than systemic. C trap and terrain code feeds shop damage, bill objects, ownership, monster blame, deaf/blind feedback, and trap visibility through common APIs (`nethack-c/upstream/src/do.c:162`, `nethack-c/upstream/src/trap.c:2996`, `nethack-c/upstream/src/trap.c:3733`, `nethack-c/upstream/src/dig.c:2050`). JS has local messages and some buried merchandise handling in floor effects, but no single context object carrying visibility, ownership, hero-caused damage, shop debt, and source/blame through trap, liquid, ray, earthquake, and burial code (`js/cmd.js:13776`, `js/monster_liquid.js:290`, `js/ice.js:725`).

## Recommended Implementation Slices

1. Introduce a shared object material/damage registry. Port the C object material flags and predicates into JS object data, then route rust/rot/corrode/burn/crack, water damage, fire damage, cold potion shattering, lava destruction, grease, blessed protection, erosionproofing, and artifact resistance through one `damageObjectByElement()`-style API. Keep message formatting per caller, but keep material decisions table-driven.

2. Build a C-shaped trap effect selector. Add one JS `trapEffectSelector(actor, trap, flags)` used by hero movement, sitting, monster movement, pet movement, and terrain callbacks. Existing `sit*` and `monster*` functions can become effect implementations, but dispatch, seen-trap escape, Sokoban exceptions, trap deletion, blame, trap knowledge, and harmless checks should live in the shared selector.

3. Add a central post-placement terrain pipeline. Implement an equivalent to `spoteffects(pick)` that runs after hero movement, teleport arrival, levitation ending, ice melt under the hero, terrain conversion, and any other direct relocation. It should own liquid checks, sink checks, pickup/trap ordering, pit exceptions, ice warnings, recursion protection, and "no private-suite special case" behavior.

4. Create reusable hero and monster liquid resolvers. Port `drown()`, `lava_effects()`, `sink_into_lava()`, and `minliquid()` in source-backed stages. First cover state transitions and death/escape outcomes, then inventory damage and special species, then messages/vision/underwater details. Replace movement-only liquid shortcuts with calls into these resolvers.

5. Make `earthFloorEffects()` the only object landing gate. Inventory drops, throws, kicks, monster deaths, monster throws, object spills, boulder motion, earthquake pits, ice melt/unearth, polymorph/statue releases, and terrain-created objects should all call one floor-effect entry point with a context carrying source, visibility, shop ownership, and hero-caused/blame flags.

6. Unify ray terrain handling behind a `zapOverFloor` port. Keep `fire_breath.js` and `ice.js` as implementation modules if useful, but introduce one ray-floor hook for fire/cold/electric/other zaps with C-like range modifiers, terrain conversion, door/web/fountain behavior, floor object burning, shop damage, and monster/hero callbacks.

7. Normalize burial and ice timers. Represent buried objects, ice melt timers, and buried organic rot in a save/restore-safe structure with stable object IDs and elapsed-turn catchup. Make freezing call `buryObjectsAt()`, melting call `unearthObjectsAt()`, and earthquake pit creation call the same burial/floor-effect pipeline.

8. Integrate earthquake through the shared primitives. Preserve the existing `doEarthquake()` surface, but move pit creation, boulder settling, object burial, monster/hero falling, liquid fill, and terrain collapse side effects into reusable helpers that match the trap/liquid/floor contracts above.

9. Add source-derived public regression coverage. Cover ordinary movement trap versus sitting trap parity, monster trap triggering, stepping/falling/teleporting into water and lava, cold ray over pool/lava/ice/door, fire ray over web/ice/water/fountain, boulder liquid fill, object damage through water/fire/lava, burial/unearth with punishment ball, and earthquake pit creation. Each test should be derived from upstream C behavior, not private-suite observations.
