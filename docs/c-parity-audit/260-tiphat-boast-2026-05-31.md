# C Parity Audit 260: Tiphat Boasting Giants

## Sources

- `nethack-c/upstream/include/monflag.h:58`: `MS_BOAST` is the giant speech sound.
- `nethack-c/upstream/include/monsters.h:1713-1774`: `giant`, `stone giant`, `hill giant`, `fire giant`, `frost giant`, and `storm giant` use `MS_BOAST`; `ettin` and `titan` use different sounds.
- `nethack-c/upstream/src/sounds.c:1006-1024`: hostile `MS_BOAST` makes exactly one `rn2(4)` roll. Roll `0` directly prints the gem-collection boast with `mhis(mtmp)`, roll `1` complains about mutton, and rolls `2` or `3` shout `"Fee Fie Foe Foo!"` and call `wake_nearto(mtmp->mx, mtmp->my, 7 * 7)`.
- `nethack-c/upstream/src/sounds.c:1024-1025`: peaceful `MS_BOAST` falls through to broad `MS_HUMANOID`.
- `nethack-c/upstream/src/sounds.c:1222-1241`: non-direct `pline_msg` output prepends `Monnam(mtmp)`.
- `nethack-c/upstream/src/sounds.c:1503-1529`: directed `tiphat()` clears wait strategy, intercepts visible humanoids before `domonnoise()`, and only reaches monster noise for adjacent fallback responders.
- `nethack-c/upstream/src/mon.c:4364-4384`: `wake_nearto()` wakes monsters with strict `dist2 < distance`, clears wait strategy only for non-unique monsters, and disturbs buried zombie corpses near the sound origin.

## JS Changes

- Added a narrow source-backed `TIPHAT_BOAST_MONSTER_NAMES` fallback for the six C `MS_BOAST` giant names.
- Added hostile `boast` handling in `tipHatMonsterNoise()` with the C `rn2(4)` table.
- Reused `tipHatMonsterPossessive()` for the gem-collection branch.
- Reused `tipHatWakeNearby(mon, 7 * 7)` for the Fee/Fie branch so the strict squared-distance behavior and visible sleeper wake messages stay aligned with the existing wake helper.

## Tests

Added focused coverage in `test/shop-billing-helpers.test.mjs`:

- `worn helmet tip makes hostile invisible boasting giant mention gems`
- `worn helmet tip makes hostile invisible boasting giant complain about mutton`
- `worn helmet tip makes hostile invisible boasting giant wake nearby sleepers`

These cover implicit giant sound inference, explicit `MS_BOAST`, `rn2(4)` rolls `0`, `1`, and default, female possessive text, invisible `It` subjects, wake message ordering, mapped invisibility, and the strict `7 * 7` boundary.

## Remaining Gaps

- Peaceful `MS_BOAST` still falls into the broad `MS_HUMANOID` speech table, which remains a separate larger slice.
- Visible giants are still intercepted by the visible humanoid `tiphat()` response before `domonnoise()`, matching the current directed path but leaving broad visible humanoid speech to the humanoid slice.
- Hallucination-specific pronoun randomization from C `mhis()` is not modeled here; the covered ordinary invisible cases use `its` or explicit monster gender.
- Buried zombie disturbance from `wake_nearto()` remains covered only by the existing shared wake helper behavior; this slice does not add new buried-corpse canaries.
