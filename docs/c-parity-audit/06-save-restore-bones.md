# 06. Save, Restore, Bones, and Cross-Level State Audit

Scope: upstream C under `nethack-c/upstream` and current JS under `js/`. This audit covers normal save/restore, level persistence, bones lifecycle, identity/timer/RNG/state serialization, and cross-level object/monster state. It does not infer anything from private suites.

## Upstream C Shape

C normal save is a two-layer format. `dosave0()` writes version data and player identity, saves the current level, saves global game state, then appends every other existing level before deleting the per-level files (`nethack-c/upstream/src/save.c:73`, `nethack-c/upstream/src/save.c:157`, `nethack-c/upstream/src/save.c:168`, `nethack-c/upstream/src/save.c:185`). `savegamestate()` covers `moves`, `context`, flags, `u`, real time, killers, global timers/lights, inventory, ball/chain, migrating objects/monsters, `mvitals`, dungeon overview, special-level chain, quest status, spells, artifacts, oracle data, fruit/names/message history/gamelog/Lua data (`nethack-c/upstream/src/save.c:265`). `savelev()` writes level identity, cemetery/bones info, map memory, level timestamp, stairs, destinations, flags, doors/rooms, level timers/lights, monsters, traps, floor/buried/bill objects, engravings, shop damage, regions, bubbles, exclusions, and track (`nethack-c/upstream/src/save.c:429`, `nethack-c/upstream/src/save.c:509`, `nethack-c/upstream/src/save.c:515`, `nethack-c/upstream/src/save.c:538`).

C restore validates file compatibility before full recovery (`nethack-c/upstream/src/files.c:1270`, `nethack-c/upstream/src/version.c:512`, `nethack-c/upstream/src/version.c:713`). `dorecover()` reads current level, restores global state, writes split level files back out, reloads the current level, deletes the save file for normal play, and relinks state (`nethack-c/upstream/src/restore.c:788`). `restgamestate()` restores global timers/lights before inventories and migrating lists, then relinks timers/lights after all objects and monsters exist (`nethack-c/upstream/src/restore.c:525`, `nethack-c/upstream/src/restore.c:652`, `nethack-c/upstream/src/restore.c:671`, `nethack-c/upstream/src/restore.c:724`). `getlev()` restores a level timestamp, computes elapsed turns, restores level timers/lights with that adjustment, reconstructs object and monster occupancy, catches up monsters, and handles bones-specific ID remapping (`nethack-c/upstream/src/restore.c:1046`, `nethack-c/upstream/src/restore.c:1110`, `nethack-c/upstream/src/restore.c:1144`, `nethack-c/upstream/src/restore.c:1181`, `nethack-c/upstream/src/restore.c:1212`).

C level changes save the leaving level, move eligible followers/accessible monsters into migration lists, then restore or create the target level and deliver objects/monsters before running timers (`nethack-c/upstream/src/do.c:1478`, `nethack-c/upstream/src/do.c:1623`, `nethack-c/upstream/src/do.c:1642`, `nethack-c/upstream/src/do.c:1698`, `nethack-c/upstream/src/do.c:1815`). `keepdogs()`, `migrate_to_level()`, `losedogs()`, and `mon_arrive()` carry destination metadata, `mlstmv`, worm segments, shopkeeper residency, pet/follower rules, failed arrivals, and elapsed catchup (`nethack-c/upstream/src/dog.c:292`, `nethack-c/upstream/src/dog.c:304`, `nethack-c/upstream/src/dog.c:420`, `nethack-c/upstream/src/dog.c:625`, `nethack-c/upstream/src/dog.c:787`, `nethack-c/upstream/src/dog.c:886`).

C bones are real level files with generated names/bones IDs and version validation (`nethack-c/upstream/src/files.c:763`, `nethack-c/upstream/src/files.c:832`, `nethack-c/upstream/src/files.c:913`, `nethack-c/upstream/src/files.c:939`). `can_make_bones()` enforces the C no-bones rules and probability (`nethack-c/upstream/src/bones.c:356`). `savebones()` removes or transforms unsafe state, creates ghost/statue/remains, strips player-specific object knowledge/names, clears map memory, adds cemetery metadata, writes ancestor UUID/bones ID/fruits, updates `mlstmv`, and saves the level (`nethack-c/upstream/src/bones.c:403`, `nethack-c/upstream/src/bones.c:541`, `nethack-c/upstream/src/bones.c:560`, `nethack-c/upstream/src/bones.c:573`, `nethack-c/upstream/src/bones.c:612`). `getbones()` validates and consumes the bones file, loads fruit data, calls `getlev()`, removes defunct monsters, resets objects/artifacts/shop damage, sanitizes engravings, increments bones count, and unlinks the file unless wizard declines (`nethack-c/upstream/src/bones.c:630`, `nethack-c/upstream/src/bones.c:662`, `nethack-c/upstream/src/bones.c:707`, `nethack-c/upstream/src/bones.c:716`, `nethack-c/upstream/src/bones.c:745`).

## Current JS Shape

JS normal save is a JSON snapshot of most enumerable `game` fields. `encodeSaveState()` skips `coreCtx`, `displayCtx`, `mockStorage`, display handles, `game.rng`, and hooks, converts top-level Maps, drops functions, converts BigInts to Numbers, and suppresses repeated object references (`js/save.js:11`, `js/save.js:20`). `restoreSaveState()` parses Maps, clears `game`, assigns the snapshot, reinstalls `GameMap` prototypes for current and saved levels, and heuristically rebinds a steed by position/name (`js/save.js:165`). The command handler writes that JSON to `game._savefile` on save confirmation and marks gameover (`js/cmd.js:35880`); `NethackGame.start()` reads it before RNG initialization, restores it, then deletes the save file and performs two RNG calls plus calendar restoration (`js/jsmain.js:194`, `js/jsmain.js:201`, `js/jsmain.js:222`). Storage is a simple VFS over localStorage or `InMemoryStorage` (`js/storage.js:27`, `js/storage.js:36`, `js/storage.js:43`, `js/storage.js:72`).

JS level persistence is in-memory. `finishLevelTeleport()` snapshots the leaving level into `game._saved_levels` with `{ level, stairs, utrack, moves }`, removes nearby carried followers, switches `u.uz`, then either restores the saved target or calls `mklev()` (`js/cmd.js:3595`, `js/cmd.js:3632`, `js/cmd.js:3636`, `js/cmd.js:3651`, `js/cmd.js:3672`). The direct `>`/`<` command paths duplicate a smaller version of that logic (`js/cmd.js:37760`, `js/cmd.js:37874`). Returned levels run glob catchup and some hider RNG/catchup behavior, but there is no C-style level file, `losedogs()`, `obj_delivery()`, or global migration-list pipeline (`js/cmd.js:2585`, `js/cmd.js:3655`, `js/cmd.js:37797`, `js/cmd.js:37911`).

JS bones are JSON snapshots in `/bones/${dnum}:${dlevel}`. Death handling checks a subset of C bones rules, creates remains, curses inventory with RNG, creates a ghost, and writes `encodeBonesLevel()` (`js/cmd.js:18162`, `js/cmd.js:18187`, `js/cmd.js:18204`, `js/cmd.js:18214`, `js/cmd.js:18261`). `encodeBonesLevel()` clones the level, zeros `mlstmv`, clears pet/tame/peaceful fields, drops inventory on the corpse/statue or floor, appends the ghost, and records a `restoreIdentityCount` (`js/save.js:86`). `mklev()` calls `getbones()` before generic level creation, and `getbones()` reads/deletes/restores that JSON with wizard prompts and burns `rnd(2)` for each counted identity (`js/mklev.js:7626`, `js/mklev.js:7652`, `js/mklev.js:7669`, `js/mklev.js:7692`, `js/mklev.js:7805`). `restoreBonesLevel()` installs the saved map, clears display memory fields, restores stairs/track, marks familiar bones, and notes whether monster turns have started (`js/save.js:134`).

JS identities use `game._next_ident` and `rnd(2)`, with objects using `id` and monsters using `m_id` (`js/mklev.js:3732`, `js/mklev.js:3904`, `js/mklev.js:6705`). RNG has separate core/display ISAAC64 contexts but save serialization explicitly skips them (`js/rng.js:21`, `js/rng.js:51`, `js/rng.js:118`, `js/save.js:11`). Timers are mostly object/location fields such as `eggHatchTurn`, `rotAwayTurn`, `reviveTurn`, `zombifyTurn`, `globShrinkTurn`, `meltIceTimers`, and `figurineTransformTurn`, with scanner-based processing for corpses/globs and a returned-level glob catchup path (`js/cmd.js:13296`, `js/cmd.js:13491`, `js/cmd.js:13711`, `js/cmd.js:13731`, `js/ice.js:89`, `js/figurine.js:19`).

## Concrete Gaps

1. Save file schema and validation are not C-like. C writes version/critical-byte metadata and rejects incompatible saves/bones; JS snapshots have no versioned schema, compatibility check, player identity header, or migration layer (`nethack-c/upstream/src/version.c:512`, `nethack-c/upstream/src/version.c:713`, `js/save.js:20`). This makes stale JSON and changed object shapes silent hazards.

2. JS serialization drops graph relationships opportunistically. The `WeakSet` replacer omits repeated references instead of preserving IDs/back-pointers (`js/save.js:26`). C serializes object/monster chains and explicitly relinks context pointers, worn objects, timers, lights, steed/ustuck, and object occupancy after load (`nethack-c/upstream/src/restore.c:67`, `nethack-c/upstream/src/restore.c:563`, `nethack-c/upstream/src/restore.c:657`, `nethack-c/upstream/src/restore.c:724`, `nethack-c/upstream/src/restore.c:1181`).

3. RNG restore behavior is port-specific and underdocumented. C RNG contexts are static core/display ISAAC64 states initialized/reseeded by startup/level code, not by the visible save stream (`nethack-c/upstream/src/rnd.c:18`, `nethack-c/upstream/src/rnd.c:42`, `nethack-c/upstream/src/rnd.c:281`, `nethack-c/upstream/src/mklev.c:1576`, `nethack-c/upstream/src/do.c:1709`). JS also skips RNG state but reinitializes from the run seed and performs two post-restore rolls (`js/save.js:11`, `js/jsmain.js:201`, `js/jsmain.js:222`). That may be intentional for deterministic replay, but it is not tied to a documented C restore step.

4. Level persistence is by live object references, not serialized level files. JS stores `level` and `stairs` objects directly in `game._saved_levels` (`js/cmd.js:3636`, `js/cmd.js:37775`, `js/cmd.js:37889`). C saves and frees a level, then restores it through `getlev()` with elapsed time, timers/lights, object placement, monster placement, and sanity checks (`nethack-c/upstream/src/save.c:536`, `nethack-c/upstream/src/save.c:560`, `nethack-c/upstream/src/restore.c:1046`). This leaves JS vulnerable to cross-level shared references and incomplete reload-side reconstruction.

5. Cross-level monster migration is simplified. JS only carries nearby followers/pets through local arrays in level-change paths (`js/cmd.js:3632`, `js/cmd.js:3746`, `js/cmd.js:37782`, `js/cmd.js:37896`). C has separate `gm.mydogs`, `gm.migrating_mons`, destination encodings, arrival order, failed-arrival handling, shopkeeper residency, Wizard/special-monster accessibility, long-worm handling, and catchup from `mlstmv` (`nethack-c/upstream/src/dog.c:304`, `nethack-c/upstream/src/dog.c:420`, `nethack-c/upstream/src/dog.c:765`, `nethack-c/upstream/src/dog.c:886`).

6. Cross-level object migration/delivery is mostly absent. C saves global `gm.migrating_objs`, delivers them on level entry before timers run, and includes them in global timer/light range decisions (`nethack-c/upstream/src/save.c:306`, `nethack-c/upstream/src/do.c:1815`, `nethack-c/upstream/src/timeout.c:2661`, `nethack-c/upstream/src/light.c:19`). JS has ad hoc impact-drop and punishment-object handling, but no general migrating object list with destination metadata.

7. Timer identity and relinking are not C-equivalent. C timers/lights are saved by global/level range, use object/monster IDs instead of pointers, adjust elapsed time for restored levels/bones, and relink through ID maps (`nethack-c/upstream/src/timeout.c:1923`, `nethack-c/upstream/src/timeout.c:2668`, `nethack-c/upstream/src/timeout.c:2707`, `nethack-c/upstream/src/timeout.c:2751`, `nethack-c/upstream/src/light.c:517`). JS stores timer fields directly on objects/locations and only has focused scanner/catchup logic for some timer families (`js/cmd.js:13296`, `js/cmd.js:13731`, `js/ice.js:89`, `js/figurine.js:19`). Off-level corpse, figurine, ice, light, and monster-carried timer parity needs explicit coverage.

8. Bones identity remapping is count-based instead of map-based. C remaps every restored bones object and monster through `next_ident()`, stores old-to-new mappings, and uses them for timers/lights and `omid`/attached monster IDs (`nethack-c/upstream/src/restore.c:231`, `nethack-c/upstream/src/restore.c:376`, `nethack-c/upstream/src/restore.c:1460`, `nethack-c/upstream/src/restore.c:1510`). JS records `restoreIdentityCount` and burns `rnd(2)` that many times, but the restored object IDs and monster IDs remain the old JSON values (`js/save.js:60`, `js/save.js:130`, `js/mklev.js:7670`). That can collide with future IDs and cannot relink attached references.

9. Bones sanitation is partial. C strips object knowledge and user names, handles fruit IDs, eggs, mail, unique corpse/statue data, invocation artifacts, ghostly flags, tame monsters, trap ownership/visibility, map memory, cemetery metadata, wizard bones, shop damage, and defunct monsters (`nethack-c/upstream/src/bones.c:51`, `nethack-c/upstream/src/bones.c:100`, `nethack-c/upstream/src/bones.c:140`, `nethack-c/upstream/src/bones.c:170`, `nethack-c/upstream/src/bones.c:541`, `nethack-c/upstream/src/bones.c:551`, `nethack-c/upstream/src/bones.c:573`, `nethack-c/upstream/src/bones.c:716`). JS clears display memory and pet/tame state and handles dropped inventory/ghosts, but does not yet implement most of that sanitation (`js/save.js:90`, `js/save.js:100`, `js/save.js:119`, `js/save.js:141`).

10. Bones file naming/lifecycle is simplified. C names bones by dungeon/special/quest bone IDs, records an internal bonesid, writes through a temporary file, validates the ID on read, and consumes/unlinks with race handling (`nethack-c/upstream/src/files.c:763`, `nethack-c/upstream/src/files.c:832`, `nethack-c/upstream/src/files.c:913`, `nethack-c/upstream/src/bones.c:678`, `nethack-c/upstream/src/bones.c:693`, `nethack-c/upstream/src/bones.c:745`). JS keys by raw `dnum:dlevel` and stores no bonesid/version/ancestor UUID (`js/cmd.js:18265`, `js/mklev.js:7632`, `js/save.js:123`).

11. No-bones rules are incomplete. JS checks flags, bottom level, branch entry levels, magic portals, depth, probability, and explore mode (`js/cmd.js:18162`). C also consults special-level and dungeon `boneid`, `Is_botlevel()`, multiway branch levels, invocation level, swallowed state, discover mode, and wizard exceptions (`nethack-c/upstream/src/bones.c:17`, `nethack-c/upstream/src/bones.c:356`).

12. Stairs and teleport restoration have duplicated, divergent code. `finishLevelTeleport()` has the fuller restore path, but `>` and `<` maintain separate snapshots, carried-follower logic, and returned-level RNG loops (`js/cmd.js:3595`, `js/cmd.js:37760`, `js/cmd.js:37874`). C centralizes the mechanics in `goto_level()` plus `keepdogs()/losedogs()` (`nethack-c/upstream/src/do.c:1478`, `nethack-c/upstream/src/dog.c:787`).

## Recommended Slices

1. Add a versioned JS save/bones schema. Keep it JSON/VFS if desired, but split sections to mirror C ownership: header, current level, global game state, saved levels, migrating mons/objs, timers/lights, and UI-only exclusions. Reject incompatible schema versions explicitly before `Object.assign()`.

2. Replace live `_saved_levels` entries with serialized level snapshots and a single restore path. Include level timestamp, stairs/destinations, map memory, rooms/doors, traps, floor/buried/bill objects, monsters, regions/engravings/tracks, bubbles, and per-level timer/light fields. Use the same path for stairs, level teleport, branch portals, and save/restore.

3. Implement C-style migration lists in JS. Add `_mydogs`, `_migrating_mons`, and `_migrating_objs` with destination metadata equivalent to `MIGR_*`, `mlstmv`, source level, arrival flags, and failed-arrival handling. Then make stairs/teleport call one `leaveLevel()` and one `arriveLevel()` pipeline.

4. Build an ID-map restore pass. For normal restore, rebuild references from IDs after all objects/monsters are loaded. For bones, assign fresh IDs to every restored object/monster with actual `next_ident()` calls, store old-to-new mappings, and update corpse/statue attached monster IDs, leash/owner references, timer targets, light targets, and any context references.

5. Centralize timers and elapsed catchup. Either introduce a registry close to C `save_timers()`/`restore_timers()` or standardize scanner metadata for every field timer. Classify each timer as global, level-local, object-carried, monster-carried, buried, or migrating; adjust by elapsed turns on level restore; run due timers after object/monster delivery.

6. Harden bones in layers. First match no-bones eligibility and file metadata/version/bonesid. Then add save-side sanitation for object knowledge/names, fruits, eggs, invocation items, trap ownership, map memory, tame/peaceful resets, unique/special monsters, and cemetery data. Finally add restore-side defunct-monster pruning, artifact/shop/engraving sanitation, and ghostly object handling.

7. Decide and document RNG semantics. If deterministic replay intentionally differs from C process-start RNG, document that and remove unexplained restore rolls or tie them to named C-visible operations. If C parity is the priority, model C `init_random()`/`reseed_random()` behavior at startup, `mklev()`, and returning to saved levels, with separate core/display contexts.

8. Add focused public regression coverage for the new slices: save/restore with carried/worn/container references, leave/return with pets and special monsters, migrating object delivery, off-level corpse/figurine/glob/ice timers, bones creation/consumption, and ID collisions after bones. Keep these as source-derived scenarios, not private-suite assumptions.
